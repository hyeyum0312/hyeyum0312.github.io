# 🔍 들어가며

대중교통 화면에는 열차의 행선지가 표시됩니다. 시간표 데이터의 종착역이 그대로 사용자 안내로 이어지기 때문에, 실제로 어떤 행선지가 나타나는지 먼저 알아야 했습니다.

평소 보는 "OO행"만 생각하면 노선마다 두세 개면 될 것 같습니다. 하지만 첫차와 막차, 출퇴근 시간대, 주말에는 평소에 보기 힘든 행선지가 나타납니다. 급행과 일반 열차도 행선지가 다릅니다. 직접 타 보는 것만으로는 이 경우를 모두 확인할 수 없었습니다.

그래서 조사는 AI에게 맡겼습니다. 이 글은 무엇을 요청했고, 돌아온 결과를 어떻게 읽었는지에 대한 기록입니다.

---

# 🔍 요청에 넣은 조건

실제로 보낸 요청은 이랬습니다.

> 수도권 전철 24개 노선 전체에 대해 평일·주말, 첫차·막차, 출퇴근 시간대의 희귀 행선지까지 포함해서 실제 표시되는 모든 행선지를 공식 시간표 기반으로 조사해 표로 정리해줘. 일반·급행도 구분하고 확인되지 않은 것은 표시해줘.

짧은 문장이지만 조건마다 이유가 있었습니다.

| 조건 | 넣은 이유 |
| --- | --- |
| 24개 노선 전체 | 자주 보는 노선만 조사하고 끝나지 않도록 범위를 고정 |
| 평일·주말, 첫차·막차, 출퇴근 | 희귀 행선지가 나타나는 시간대를 명시 |
| 공식 시간표 기반 | 블로그나 커뮤니티의 오래된 정보가 섞이지 않도록 출처를 지정 |
| 일반·급행 구분 | 같은 노선이라도 행선지가 달라지는 운행 종류를 분리 |
| 확인되지 않은 것은 표시 | 조사한 것과 추정한 것을 결과에서 구분 |

가장 중요하게 생각한 건 마지막 조건이었습니다. 조사 결과가 표로 깔끔하게 정리돼 있으면, 그 안의 모든 칸이 확인된 사실처럼 보이기 쉽습니다.

---

# 🔍 돌아온 결과는 '전수 목록'이 아니었다

AI가 정리한 표는 이렇게 시작했습니다.

> 최신 공식 시간표의 열차별 종착역을 모두 추출하지는 못했기 때문에, 아래는 검증 완료된 전수 목록이 아니라 현재 운행 계통을 중심으로 한 1차 정리표입니다.

요청한 건 모든 행선지였지만, 돌아온 건 주요 운행 계통 중심의 정리였습니다. 표의 일부는 이런 모습이었습니다.

| 노선 | 현재 운행 계통의 주요 행선지 | 추가 확인 |
| --- | --- | --- |
| 3호선 | 대화, 구파발, 지축, 오금 | 막차 단축 운행 |
| 9호선 | 개화, 김포공항, 중앙보훈병원 | 급행·중간 종착 |
| GTX-A | 운정중앙, 서울역, 수서, 동탄 | 현재 구간 연결 상태와 종착 표시 |

노선마다 "추가 확인" 칸이 있었고, 첫차·막차, 출퇴근 시간대, 주말 행선지는 아직 검증하지 못했다는 설명이 붙어 있었습니다. GTX-A는 구간 연결에 따라 행선지가 달라질 수 있어, 과거의 분리 운행 상태를 현재 운행으로 확정하지 않았다고 적혀 있었습니다.

요청과 결과 사이에 차이가 있었던 셈입니다. 그래도 이 차이가 결과 안에 드러나 있었기 때문에, 어디까지 믿고 어디부터 다시 확인할지 판단할 수 있었습니다. "확인되지 않은 것은 표시해 줘"라는 조건이 없었다면, 같은 표가 완성된 전수 목록처럼 보였을 수도 있습니다.

# 🔍 출처의 갱신일도 결과의 일부였다

결과 끝에는 확인한 공식 자료의 갱신일이 정리돼 있었습니다.

| 자료 | 확인된 갱신일 |
| --- | --- |
| 서울교통공사 역별 열차 시간표 API | 2026.10.15 |
| 서울교통공사 막차 시간표 API | 2026.10.07 |
| 철도 데이터 포털 전체 기관 운행정보 | 2026.07.06 |
| 철도 데이터 포털 코레일 운행정보 | 2026.07.06 |
| 서울교통공사 전체 시간표 CSV | 2025.09.30 |

같은 "공식 시간표"라도 자료마다 갱신 시점이 1년 가까이 차이 났습니다. 예를 들어 [서울 열린데이터광장의 열차운행시각표 CSV](https://data.seoul.go.kr/dataList/OA-22522/L/1/datasetView.do)는 1~9호선의 역별 도착·출발 시각과 종착역을 담고 있지만, 파일 날짜는 2025년 9월입니다. 이 파일로 찾은 행선지는 최신 시간표에서 달라졌을 수 있습니다.

그래서 공식 자료라는 사실만큼, 언제 기준의 자료인지도 함께 봐야 했습니다.

# 🔍 이 조사로 정한 것

이 조사의 목적은 막차와 단축 운행, 중간 종착처럼 평소에 잘 보이지 않는 행선지까지 화면에 정확히 표시하는 것이었습니다.

막차 시간대에는 평소와 다른 역에서 운행을 마치는 열차가 있습니다. 이걸 모르고 평소 행선지만 기준으로 안내하면, 사용자는 실제로 타지 못하는 열차를 기다리게 될 수 있습니다. 막차가 끝난 뒤 다음 열차를 어떻게 보여줄지는 [실시간 조회 기준 글](/13th/)에서 다룬 것처럼 날짜 경계와도 얽혀 있었습니다.

돌아온 표는 그 기준을 바로 정해 주는 정답은 아니었습니다. 대신 어느 노선의 어느 시간대가 아직 확인되지 않았는지 알려 주었습니다. 3호선의 막차 단축 운행, 1호선의 운행 계통별 중간 종착, GTX-A의 구간 연결 상태처럼, 공식 시간표와 다시 대조해야 할 곳이 표 안에 드러나 있었습니다.

그래서 이 표는 결과가 아니라 확인 목록으로 읽었습니다. 확인된 행선지는 기준으로 삼고, "추가 확인"으로 남은 항목은 최신 공식 시간표로 다시 확인할 대상으로 구분했습니다.

# 🔍 마치며

AI에게 조사를 맡기면 사람이 직접 하기 어려운 범위를 빠르게 훑을 수 있습니다. 하지만 결과를 쓰려면 그 결과가 무엇을 근거로 하고, 어디까지 확인됐는지 알 수 있어야 합니다.

그래서 요청에는 범위와 출처, 확인 상태를 표시하는 조건을 함께 넣고, 결과를 받으면 확인된 것과 확인이 필요한 것, 자료의 기준 시점을 나눠서 읽습니다. [AI와 함께 일할 때, 내가 먼저 정하는 것들](/15th/)에서 정리한 완료 보고를 읽는 기준을 리서치에도 그대로 적용한 셈입니다.
